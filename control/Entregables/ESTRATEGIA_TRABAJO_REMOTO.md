# Estrategia De Trabajo Remoto Por Objetivos

Proyecto: IO Group Web - Control  
Fecha base: 2026-05-05  
Estado actual: Semana 1 completada  
Semana de inicio remoto: Semana 2 - Catalogos base

## Objetivo

Organizar el trabajo remoto por entregables semanales claros, medibles y verificables por jefatura sin necesidad de revisar codigo ni conocer programacion.

El avance se medira por resultados funcionales, capturas, documentos de avance y checklist actualizado.

## Modelo De Trabajo

| Elemento | Definicion |
|---|---|
| Modalidad | Trabajo remoto de lunes a viernes |
| Medicion | Entregables semanales cerrados |
| Evidencia | Demo, capturas, checklist y documento de avance |
| Seguimiento | `task.md` actualizado al cierre de cada semana |
| Reporte | Documento semanal con hecho, pendiente y bloqueado |
| Validacion | Jefatura revisa resultados visibles, no codigo |

## Reuniones Minimas

| Dia | Duracion | Objetivo |
|---|---:|---|
| Lunes | 15 minutos | Confirmar objetivo semanal y dependencias |
| Miercoles | 10 minutos | Informar avance, bloqueos y riesgos |
| Viernes | 30 minutos | Mostrar demo, capturas y cierre de semana |

## Calendario De Entregables

| Semana | Objetivo Para Jefatura | Resultado Esperado | Estado |
|---|---|---|---|
| Semana 1 | Base tecnica y despliegue | Sistema preparado tecnicamente, PHP validado, rutas y guia de deploy corregidas | Completado |
| Semana 2 | Catalogos base | Clientes, sedes, empresas, vehiculos, plantas, empleados y usuarios revisados con datos reales | Siguiente |
| Semana 3 | Operacion diaria | Servicios, calendario, asignacion de rutas, historial y control de ruta funcionando como flujo operativo | Pendiente |
| Semana 4 | Documentos y altas | Altas, firma digital, contratos, facturas, guias y manifiestos revisados y corregidos | Pendiente |
| Semana 5 | Finanzas | Ingresos, egresos y cobranza validados con conciliacion basica | Pendiente |
| Semana 6 | Control gerencial | Dashboard, reportes, alertas y mapa corregidos para seguimiento de gestion | Pendiente |
| Semana 7 | Seguridad y permisos | Usuarios, permisos, API keys, archivos sensibles y scripts de debug protegidos | Pendiente |
| Semana 8 | QA y salida | Pruebas finales, UAT con usuario final y version candidata para produccion | Pendiente |

## Reglas De Ejecucion Semanal

1. Cada lunes se define un objetivo de negocio en una sola frase.
2. Cada modulo trabajado queda marcado como listo, pendiente o bloqueado.
3. Cada viernes se entrega una version revisable con capturas y demo breve.
4. Todo bloqueo externo se registra el mismo dia con responsable y alternativa.
5. Todo pendiente queda escrito en `task.md`; no se manejan pendientes invisibles.

## Indicadores De Avance

| Indicador | Forma De Medicion |
|---|---|
| Etapas completadas | Numero de etapas cerradas sobre 8 |
| Pantallas validadas | Capturas incluidas en el reporte semanal |
| Flujos probados | Checklist por modulo |
| Bloqueos abiertos | Lista de bloqueos con responsable |
| Riesgos criticos | Registro de riesgos antes de produccion |
| Version revisable | Demo semanal funcional |

## Criterios De Aceptacion Semanal

Una semana se considera cerrada solo si:

- La funcionalidad principal abre en navegador.
- El checklist de la semana queda actualizado.
- Existen capturas del avance.
- Los errores encontrados quedan registrados.
- Jefatura puede ver un resultado concreto sin revisar codigo.

## Responsabilidades

| Rol | Responsabilidad |
|---|---|
| Desarrollo | Ejecutar tareas, corregir errores, documentar avances y preparar demo |
| Jefatura | Revisar resultado visible, validar prioridades y entregar accesos o datos requeridos |
| Usuario final | Probar flujos cuando aplique y reportar observaciones |

## Evidencia Esperada Por Semana

- Documento `AVANCE_SEMANA_X_*.md` o `.doc`.
- Capturas pegadas en el documento de avance.
- Checklist actualizado en `task.md`.
- Lista de bloqueos, si existen.
- Resumen de siguiente semana.

## Supuestos

- La jornada remota mantiene el mismo compromiso laboral que la jornada presencial.
- La evaluacion se centra en resultados semanales.
- Los accesos, credenciales y datos reales se entregan cuando sean necesarios.
- Si faltan datos reales, se usaran datos de prueba hasta recibirlos.
- La revision de jefatura sera funcional y visual, no tecnica.
